Security I build in

A store handles other people’s passwords and orders, so I treat security as part of the build, not an extra.

Passwords are never stored as text.They are saved as salted hashes, so even I can’t read them.
Login cookies are locked down.They can’t be read by page scripts or sent from other websites.
The server decides, not the browser.Prices, stock and who may see which order are checked on the server.
Abuse is slowed down.Repeated wrong logins are locked out for a while, and oversized requests are rejected.
Admins get extra protection.MOSSTECH supports authenticator-app sign-in and keeps an audit log of admin actions.
The browser is told what to trust.Content-security and anti-framing headers limit what a page can load or be embedded in.

No system is perfectly secure. On the public demos I turned off email verification and admin two-step sign-in so visitors can try them, and they run on free hosting with sample data. For a real store that takes payments, we plan a security review, payment handling and backups into your quote.
